# Browser-native Melee feasibility spike (September 15, 2026)

The port has now started: see [implementation status](BROWSER-NATIVE-PORT-STATUS.md)
and [reproducible native build](../engines/browser-native/README.md). The findings
below describe the earlier feasibility probes.

The [matching USA 1.02 decompilation](https://github.com/doldecomp/melee/tree/a75407433c85ac15fab45f92ff79c1481f1fa82f) makes a browser-native Melee runtime technically credible. It is not a browser release: the upstream build produces GameCube `main.dol` and its documented play path uses Dolphin. A direct port could remove PPC block translation and interpreter dispatch, which dominate the measured CPU work in the current browser build. Its actual FPS benefit remains unmeasured.

In a disposable external checkout at commit `a75407433c85ac15fab45f92ff79c1481f1fa82f`, there are 1,032 C source files and two assembly files. A temporary `__EMSCRIPTEN__` guard around the project's conflicting `ssize_t` typedef was the only change needed for Emscripten to parse representative fighter (`fighter.c`), stage collision (`mpcoll.c`), HSD polygon rendering (`pobj.c`), and main scene (`gmscene.c`) translation units. A sweep parsed 952 of all 1,032 C files without other fixes. Fifty-nine of the 80 failures are stage files, most rejected for the same `void(bool)` versus `void(int)` callback signature mismatch. A second syntax-only sweep suppressing that callback diagnostic parsed 1,009/1,032 files; 23 remained, including SDK/MSL libc headers, generated font includes and genuine decompilation type conflicts. Suppression is only an exploration tool; type mismatches must be fixed or audited before a release. Both `mpcoll.c` and `pobj.c` compiled to wasm objects. The polygon object has unresolved GXBegin/display-list/array/vertex/matrix calls, making the graphics shim boundary concrete. Compile-time assertions passed for 32-bit pointers, `CollData.x130_flags` offset `0x130`, `HSD_JObj.flags` offset `0x14`, its union offset `0x18`, and HSD JObj size `0x88`.

A 1.1 KiB WASM probe linked the actual decompiled `mpCollInterpolateECB` collision routine with a temporary test harness. Running it in Node produced exactly the expected interpolated four ECB coordinates and preserved previous ECB values (`[4, -6, -5, 7, 2, -4]`). A second build targeted `ENVIRONMENT=web` and linked without undefined-symbol suppression using explicit probe-only `OSReport`/`__assert` shims. Chrome loaded the WASM over a private local static server, executed the actual C routine, and reported the same six expected values with `passed:true`. The assertion path was not exercised. These are source/ABI/browser-execution smoke checks, not browser gameplay, linked whole-game execution, parity, or an FPS measurement.
[Browser proof report](benchmarks/browser-2026-09-15-native-decomp-browser-proof.json).

The hard work is an explicit browser platform layer. Melee code calls GameCube OS/scheduler, DVD/asset loaders, GX, audio, controller, memory/ARAM and SDK math services. The decomp checkout includes 148 C files under `libs`, including the GX SDK's higher-level state/geometry functions. Its low-level `GXVert.h` still writes through `GXWGFifo` at fixed address `0xCC008000`; browser code must route those writes and other GPU registers to a native GX translator instead of dereferencing MMIO. Browser WASM is little-endian while the hosted disc and several native structures are big-endian. Asset relocation, bitfields, floating-point behavior, memory ownership and fixed GameCube addresses need auditing before direct C state can replace the emulated DOL. The native camera, 4:3 projection, tournament rules, all fighters and moving gameplay objects must remain equivalent. Existing hosted automatic startup remains mandatory; players never supply an ISO. Static Vercel hosting is feasible if all assets and platform code run client-side, but package size and load time need measurement.

A useful first vertical slice is a browser-native match simulation for one fighter pair and one legal stage, driven by fixed per-frame input and initialized from the same hosted game data as the emulator. Compare stage/collision, fighter, RNG, camera, rules and action state against Dolphin at every frame. Then add all fighters/stages, native HSD/GX rendering and audio, and measure 960×720 distinct-image cadence and input-to-image delay. Until the slice passes parity and visible output, do not replace the playable emulator path or claim 720p60.

A shorter intermediate option is native recompilation of the measured HSD drawing/matrix hotspots inside the current core. That still requires exact guest-memory, FIFO and scheduler side effects. The September 15 GX helper attempt illustrates the risk: visible/gameplay fingerprints can match while full-machine replay differs.
